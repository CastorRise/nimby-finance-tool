# NIMBY · 财务地图分析台

把 NIMBY Rails 的**线路/站点 JSON** 与 **会计账目 TSV** 导入后，在世界真实地图上查看线路、站点与热度，
逐线逐站分析盈亏、走势与历史对比，并支持数据保存、选择性对比、打包导出跨设备使用。
纯本地运行（浏览器），Windows / macOS 通用。

---

## 一、快速开始

1. **获取游戏导出文件**（在 NIMBY Rails 游戏中）
   - 会计账目：`Accounting Export *.tsv`
   - 线路时刻表：`Timetable Export *.json`
   （两个都导最好；只导一个也能用，只是地图或财务缺一半）

2. **启动本工具**（任选其一）
   | 平台 | 方式 |
   |---|---|
   | macOS | 双击 **`启动.command`**（自动开本地服务并打开浏览器） |
   | Windows | 双击 **`启动.bat`**（或 `start-win.bat`，均为纯英文内容，不会乱码） |
   | Windows | 直接双击 **`index.html`** 也行（无需安装，同样支持本地存档） |
   | 注意 | **`启动.command` / `start-mac.command` 是 macOS 脚本，Windows 上双击会以乱码打开，请不要使用** |
   | 任何平台 | 直接双击 **`index.html`**（无需安装；个别浏览器限制本地存档时请用上面脚本方式） |

3. **导入**：点顶部「＋ 导入数据」，把两个文件**一起拖入**（可多选），按提示确认。
   等待数秒解析（大文件正常），即进入分析界面。

> 需要联网加载地图底图（CARTO/Esri/Mapbox）；所有账目与统计均在本地计算，不上传任何数据。

**地图空白排查**
- 若能看到站点圆点/线路、但底图一片灰白：是**底图瓦片被网络屏蔽或限流**。
  地图上方会自动弹出黄色提示条，可一键切换 Mapbox / CARTO / Esri / **纯色底图(离线可用)**；线路热度不受影响。
- 想用 Mapbox：点地图右上角 **M** → 设置一次 Mapbox Access Token（`pk.` 开头）。
- 若整块地图区都没有站点圆点：请强制刷新一次（macOS ⌘⇧R / Windows Ctrl+Shift+R），确保加载到最新版本；
  并请**始终用同一种方式打开**（建议始终双击 index.html 或始终用同一个启动脚本），因为浏览器按“打开方式”分别保存数据。

## 二、功能

- **真实地图**：站点按真实经纬度标注；线路按游戏配色绘制。
- **外观**：顶部「◐」可在跟随系统、浅色、深色之间切换；外观选择只保存在当前浏览器。
- **站点热度**：圆点颜色/大小 = 登乘、到达、票款、换乘…（左栏可选指标；配色、标尺在「更多地图设置」中）
- **线路热度**：线宽/颜色 = 运营利润、客流、票款…（红色亏损、绿色盈利的“盈亏分色”模式）
- **地图区域显示**：自动按城市聚类（郑州/东京/长沙/西安…），点选区域聚焦局部网络；财务汇总仍为全网
- **底图切换**：默认使用 CARTO 暖色；地图右上角可切 CARTO 暖色 / 深色 / Esri 卫星 / 纯色底图；点 **M(Mapbox)** 可切 Mapbox
  街道 / 浅色 / 深色 / 卫星（首次会提示输入 **Mapbox Access Token**，只保存在本机浏览器、不上传；无 Token 时仍可用 CARTO、Esri 和纯色底图）
- **周期粒度**：日 / 周 / 月 / 季 / 年 / 累计（全部周期），配合账期下拉选择某一天/周/月
- 注：游戏导出的**站点**账目只有“日/累计”；选择 周/月/季/年 时，站点表会自动把日账汇总成所选账期
  （表格下方会标明“覆盖 N 天 (起始日 ~ 结束日)”）；若所选账期在日账覆盖范围外会给出提示和可用账期
- **页面**：
  - `运营总览`：公司经营走势 + 客流运力 + 线路利润构成环形图 + 盈亏排行
  - `运营诊断`（自动分析）：运营参考评分(0-100) + 能力雷达 + 核心结论 + 分级建议卡片
    （亏损线路归因、运力松紧、退票赔偿、客流集中度、低流量站点、环比趋势、资产与现金流建议），
    分析报告可**直接在网页内阅读**（文档式视图，支持 🖨 打印/存 PDF、⧉ 复制 Markdown、⤓ 下载 .md），
    并可从建议卡片直接地图定位 / 跳转线路表
  - `线路财务`：逐线票款/成本/运营利润/利润率/每公里利润…可排序、搜索、导出 CSV；
    可勾选「含公司级分摊」把公司级退票/补偿/差额按票款比例摊到线路
  - `站点客流`：登乘/到达/换乘/等待超时/票款…与 Top 图表
  - `走势趋势`：公司多指标走势 + 头部线路利润走势
  - `历史对比`：见下
- **历史对比**：再次导入一份**更早或扩建前**的导出 → 「⇄ 对比分析」，选基准/对比档案与主指标，
  查看公司摘要、线路/站点逐条增减（新增/停运标记）、差额排行图与双线走势；可**保存对比**。
- **数据保存**：档案与对比自动保存在本机浏览器（IndexedDB）。
- **导出与备份**（右上角）：
  - 逐个导出档案 / 打包成**一个文件**（`.nb.json`，含几何+账目+对比，跨设备拷走即可）
  - 整库备份 / 从备份或数据包恢复（自动合并、跳过重复）
  - 表格随时导出 CSV（Excel/WPS 可用）

## 三、自动运营诊断（评分口径）

「运营诊断」页根据当前账期的账目事件给出**工具自定的参考分**，并非游戏官方评分。四个维度数据齐全时才计算总分；缺失字段显示“—”，不会作为零损失计分：

| 维度 | 权重 | 口径 |
|---|---|---|
| 盈利能力 | 45% | 运营利润率（净票款−运营成本）/净票款，−25%→0、0%→50、+25%→100 |
| 票款留存 | 20% | （退票+补偿）金额/原票款收入，损失 0%→100、20%→0 |
| 服务保障 | 20% | 获赔乘客/已开始行程乘客，获赔 0%→100、10%→0 |
| 准点表现 | 15% | 累计晚点时长/发车次数，分摊晚点 0 分钟→100、10 分钟→0 |

权重与阈值是本工具的诊断参考线，不是游戏规则。原“需求增长”分项已移除：登乘客流环比受人口分布、车站覆盖、每周时段和玩家自定需求曲线影响，只保留为趋势说明，不计入健康分。成本已进入运营利润，不再通过成本效率和维护占比重复加权。`pax_spawned` 是已开始行程乘客，不能直接当作全网潜在需求。

乘客可能跨账期完成行程或获得赔付，因此日账的获赔比例只作提示；不同需求设置下的分数不宜直接比较。

依据：[开发者对 1.12 需求系统的说明](https://carloscarrasco.com/nimby-rails-march-2024/)解释了人口位置、每周时段与自定曲线，并说明旧版车站满意度机制已停用；[开发者对退票及补偿的解释](https://steamcommunity.com/app/1134710/discussions/0/3050608970468612046/)说明了行程失败后的退款与额外补偿。分数区间是本工具的设计选择。

规则化建议包括：亏损线路逐条归因（客流不足 / 单位成本高 / 票价偏低 / 班次偏密）、
运力偏松与偏紧线路、盈利标杆与换乘枢纽、退票赔偿与晚点、站点客流集中度与低流量站点、
环比恶化与改善线路、公司现金流与长期累计盈亏。分析范围为当前档案的**全部线路**（不受地图区域筛选影响）。

## 四、跨设备使用

1. 设备 A：导出与备份 → 勾选档案 → **打包为一个文件**（或逐个导出）。
2. 把 `.nb.json` 拷到设备 B（微信/网盘/U盘皆可）。
3. 设备 B 打开本工具 → 「＋ 导入」→ 选该文件 → 自动并入，数据完整可复算，可与本地档案再对比。

## 五、指标口径（重要）

账目行中**负数表示支出**（成本、退票、补偿、建设、购车、利息等），正数表示收入。

| 指标 | 公式 |
|---|---|
| 票款净额 / 营业收入 | 票款 + 退票 + 补偿 |
| 运营成本（正数显示） | −(运行 + 维护 + 干预) |
| 运营利润（毛利） | 票款净额 − 运营成本 |
| 运营利润率 | 运营利润 ÷ 票款净额 |
| 平均票价 | 票款净额 ÷ 登乘客流 |
| 公司现金流 | 含建设/购车/售车/融资/利息的公司级现金变动 |

- 线路/站点账目只含**运营**部分；**建设与购车等资本支出只记在公司级**。
  想看含资本支出的整体盈亏请用「累计」粒度查看公司数据。
- 退票、补偿等常只记在公司级行 → 线路表默认不含，勾选「含公司级分摊」后按票款占比摊入。

## 六、目录结构

```
nimby-finance-tool/
├─ index.html            # 应用入口(双击可直接用)
├─ 启动.command / 启动.bat  # 一键启动(macOS/Windows)
├─ assets/css/style.css  # 界面样式
├─ vendor/leaflet|echarts # 本地化的地图与图表库(离线不依赖 CDN)
└─ src/                  # 解析、引擎、存储、地图、图表、对比、导出、诊断等模块
   ├─ advisor.js         # 自动运营分析与建议规则引擎
```

**隐私**：全部数据留在浏览器本地，关闭/刷新不丢失（除非浏览器清理站点数据）。
定期在「导出与备份」做一次**整库备份**更稳妥。

> 提示：本工具按游戏导出的实际字段解析（Header 名称匹配）；不同游戏版本字段变化时可把
> Accounting TSV 表头发我以适配。
